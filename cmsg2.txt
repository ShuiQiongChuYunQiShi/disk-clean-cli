fix(ci): step-level permissions made the whole workflow file invalid

build.yml has been failing on every push since e2d7c6b, and the symptom was
misleading: each run failed instantly with no jobs at all, and the run name
showed up as the file path (`.github/workflows/build.yml`) instead of the
workflow's declared name (`build`). GitHub rejects the file outright when
`permissions` appears on a step -- it is only allowed at workflow or job level.
Five consecutive pushes went red before this was traced.

Move the write permission to the job, which is where it belongs: this single job
both builds and, on tags, publishes the release. Workflow level keeps
`contents: read` so the default token stays minimal everywhere else.

Add test/ci-workflow.js so the class of mistake cannot come back silently. The
repo has no runtime dependencies and the suite runs before `npm ci`, so it does
indentation-aware structural validation instead of pulling in a YAML parser:
every workflow's top-level, job-level and step-level keys are checked against
the Actions schema, with `permissions` additionally constrained to indent 0 or 4.
Verified by injecting the bad step-level key back in and confirming the test
fails, then restoring.

Suite is now 10. Also confirmed locally exactly what CI runs: the recursive
`node --check` over bin/lib/scripts/test plus the two gui/web files, all clean.
