# disk-clean v0.7.2 发布说明

> 主题：**让它对最真实的磁盘有用**。
> 这一版集中修"只有在真实使用中才会暴露"的问题——分类在游戏/模型盘上失效、
> 错误消息是死路、GUI 每次启动都弹 UAC、报告只能看最近一份。
> `docs/PRODUCT-REVIEW.md` 的 P0–P3 事项已**全部完成**。

---

## 一、最大的一项：文件分类在真实磁盘上终于有用了

**此前的情况**：在一台 588 GB 的真实磁盘上，最大的分类是「其他」——**76.6%**。
榜首叫"未分类"。原因是规则表是按"通用办公文件"写的，而那块盘被游戏资产
（`.pak` 一个就 **296.88 GB**）和 AI 模型权重（`.safetensors` 41.87 GB）占满。
也就是说：**在最需要它给答案的场景里，这个功能什么也没说。**

**现在**：「其他」降到 **11.8%**。具体做了两件事：

| 做法 | 说明 |
|---|---|
| 补规则 | 新增「游戏资产 / AI 模型 / 开发产物 / 移动安装包」四类，以及 `models`、`hf_cache`、`wegameapps`/`steamapps`、`backup`/`xwechat_files` 等目录规则 |
| 两级判定 | 扩展名优先，扩展名不足以判断时用**目录语境**兜底。`.bin`/`.dat`/`.pack` 这类名字本身不携带用途信息——同一台机器上它们可能是模型权重、固件或游戏数据 |

另外，**无扩展名**的文件现在单独成类（真实盘上 31.87 GB，排在所有扩展名的第 4 位），
而不是混进"其他"。

### 报告里新增「未分类占用 Top」

这是本次最实用的一处：报告会列出**占用最大却没有规则覆盖**的扩展名。

在此之前，规则缺口只是一个"其他 XX%"的大数字，没人知道该补什么；
现在它直接指明目标（例如 `pak 296.88 GB 未分类`）。

> 诚实说明：`.bin`/`.dat`/`.pgf`/`.enc`/`.dsv` 仍然留在「其他」里，测试专门断言这一点。
> 给它们硬塞一个分类只是把"其他"改个名字，仍然没有信息量——它们确实需要目录语境才能判断。

## 二、GUI 不再每次启动弹 UAC

安装包此前要求 `requireAdministrator`，理由是"MFT 扫描 / 清理 / 去重 / 整理都需要"。
**这个理由是错的**：常规扫描、清理、整理、去重都不需要管理员权限。真正需要的只有
MFT 直读、SMART 健康检查、配额分析（三个都读底层卷信息）。

现在改为按需提权：默认以普通权限启动（不再弹 UAC），那三个功能在缺权限时会**明确告诉你**
"右键 → 以管理员身份运行"，而不是给你一句晦涩的失败。

## 三、错误消息不再让人猜

| 你输入的 | 以前 | 现在 |
|---|---|---|
| `disk-clean clean` | `未知清理类型: undefined` | `缺少清理类型` + 可选值列表 + 示例 |
| `disk-clean clean junk` | `未知清理类型: junk` | `未知清理类型: junk。是否想用 junk-temp？` |
| `disk-clean clean emty-dirs` | 同上，无提示 | `是否想用 empty-dirs？`（拼写距离） |
| `disk-clean scna` | `未知命令: scna` | `未知命令: scna。是否想用 scan？` |

**无关输入不会乱猜**（输入 `zzzzzzzz` 就是没有建议）——乱猜一个比不猜更让人困惑。

### 新增 `disk-clean doctor`

第一次用不知道从哪开始？跑这个：

```
✗ disk-clean doctor
  ✓ Node 运行时        v22.21.1
  ✓ 状态目录可写        C:\Users\...\.disk-clean
  ! 管理员权限          未提权（常规扫描不需要，mftscan/quota/health 需要）
  ! 最近报告            还没有扫描过
  ✓ 回收站可访问        可读

  建议的下一步：
    1) disk-clean scan D:\          扫描并生成报告
    2) disk-clean report            查看报告与建议
    3) disk-clean clean junk-temp   预览清理（默认 dry-run）
```

## 四、更安全的扫描与更好读的进度

**多范围扫描需要确认**（`scan C:\ D:\`）。以前会直接开跑；现在先列出：

```
将扫描 2 个范围：
  · C:\（已用 373.0 GB / 共 476.9 GB）
  · D:\（已用 600.1 GB / 共 931.5 GB）
→ 确认无误后加 --yes 重跑：disk-clean scan C:\ D:\ --yes
```

理由很实际：扫描是只读的，但**范围搞错**的代价是几分钟的无谓遍历，或者以为全覆盖其实漏了。
单个范围不要求确认——命令行本身就是范围。

**进度反馈**：在管道或 CI 日志里，以前每 0.8 秒写一次回车覆盖，会把日志刷成一堆互相覆盖的半行；
现在每 3 秒打一行。

> 一个刻意的取舍：**本版不给百分比，也不给 ETA**。扫描前并不知道总量（要遍历完才知道），
> 画一个百分比是编造而非测量。改为给出已处理量、已用时间与**吞吐速率**——足够判断
> "在动"还是"卡住了"——真实总量在结束时给出。

## 五、报告可以导出、可以回看

- **`disk-clean report --html`**：导出**自包含单文件** HTML（样式内联、不引用任何外部资源），
  双击能开、发给别人也能开、十年后大概率还能开。
- **GUI 启动时加载最近报告**：以前打开界面是空的，只有刚扫完那次才显示内容——
  而报告是全局单例、每次扫描覆盖，"上次扫出什么"恰恰是最常见的使用场景。
- **GUI 也能看历史**：`GET /api/reports`（清单）与 `?file=<name>`（单份归档）。

## 六、对使用者的影响

**不需要你做任何迁移。** 唯一的行为变化是 `scan` 传多个范围时需要加 `--yes`。

如果你之前觉得"分类没什么用"——那是真的，本版修好了，值得重新扫一次看看。

| 渠道 | 操作 |
|---|---|
| GUI 安装器 | 下载 `disk-clean-setup-0.7.2.exe` 覆盖安装（**这次之后启动不再弹 UAC**） |
| 单文件 exe | 下载 `disk-clean-win-x64.exe` 替换旧文件 |
| npm | `npx -y disk-clean@0.7.2 mcp`（或 `npm i -g disk-clean@0.7.2`） |

校验：

```powershell
Get-FileHash disk-clean-win-x64.exe -Algorithm SHA256   # 与发布页 values 比对
.\disk-clean-win-x64.exe build-info                     # commit 应等于本次 tag 指向的提交
```

## 七、对贡献者：能力一致性现在有守门了

`docs/CAPABILITY-MATRIX.md` 列出 24 条能力在 CLI / MCP / GUI 三面的可用性，
`test/capability-matrix.js` **双向**校验：

- 矩阵里写的入口必须真实存在（防"文档承诺了不存在的入口"）
- 实现里的入口必须都在矩阵里（防"加了能力忘了登记"）

实测有效：开发过程中新加的 `doctor` 命令与 `/api/reports` 端点，**两次都被它在登记之前拦下**。

它同时规定：已登记的欠债**不能在修复之前从文档里删掉**（那等于把问题抹掉），
而修好之后**必须留下记录**（否则同一个不对称会被重新引入）。当前欠债为零。
